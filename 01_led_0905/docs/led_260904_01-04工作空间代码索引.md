# 01_ws

## 题目

**发光二极管全亮闪烁三次后，灯全灭。**

## 程序特点

这是 `00_ws` 的 **for 循环版本**。

核心结构：

```c
for(i = 0; i < 3; i++)
{
    P0 = 0x00;
    delay();

    P0 = 0xFF;
    delay();
}
```

在这块实验板上：

```text
P0 = 0x00 → 8 个 LED 全亮
P0 = 0xFF → 8 个 LED 全灭
```

因此程序效果：

```text
全亮
↓
全灭
↓
全亮
↓
全灭
↓
全亮
↓
全灭
↓
保持全灭
```

## 看到 `01_ws` 时要想到

**最基础的 LED 三次闪烁 + for 循环。**

# 02_ws

## 题目

**发光二极管全亮闪烁三次后，灯全灭，继电器吸合，蜂鸣器响一下。**

## 新增硬件

```c
sbit RELAY = P0^4;
sbit BEEP  = P0^6;
```

对应关系：

```text
P0.4 → 继电器
P0.6 → 蜂鸣器
```

在本实验板上：

```text
P0.4 = 1 → 继电器吸合
P0.6 = 1 → 蜂鸣器响
```

## 相比 01_ws 最重要的新知识

`02_ws` 不再长时间直接写：

```c
P0 = 0xFF;
```

因为：

```text
0xFF = 11111111
```

其中同时包含：

```text
P0.4 = 1
P0.6 = 1
```

如果直接保持，会导致继电器和蜂鸣器误动作。

因此加入了：

```c
LED_Write(unsigned char dat)
```

其思路是：

```text
选择 Y4
↓
把 LED 数据写到 P0
↓
让 74HC573 锁存 LED 状态
↓
离开 Y4
↓
马上 P0 = 0x00
↓
关闭蜂鸣器和继电器
```

LED 已经由 74HC573 保存状态，所以之后把 P0 清零不会改变刚才锁存的 LED 状态。

## 程序最终流程

```text
上电先 P0 = 0x00
↓
LED 全亮
↓
LED 全灭
↓
重复 3 次
↓
LED 保持全灭
↓
RELAY = 1
↓
继电器吸合
↓
BEEP = 1
↓
蜂鸣器响一段时间
↓
BEEP = 0
↓
蜂鸣器停止
↓
继电器保持吸合
```

## 实际使用注意

开发板上的 **蜂鸣器和继电器有各自的硬件开关**。

如果对应开关没有打开，即使程序正确：

```text
继电器也不会吸合
蜂鸣器也不会响
```

这是这次排查时确认过的实际使用条件。

## 看到 `02_ws` 时要想到

**LED + 继电器 + 蜂鸣器，以及第一次真正使用 74HC573 的“锁存”来避免蜂鸣器乱响。**

# 03_ws

## 题目

**LED 灯全亮闪烁一次，蜂鸣器响 1 次；此过程循环 3 次后全灭。**

## 一轮的动作

每一轮：

```text
LED 全亮
↓
等待
↓
LED 全灭
↓
等待
↓
蜂鸣器响一次
↓
蜂鸣器停止
```

然后：

```text
整轮重复 3 次
```

最后：

```text
LED 全灭
蜂鸣器关闭
继电器关闭
```

## 蜂鸣器控制

程序使用：

```c
P0 = 0x40;
```

因为：

```text
0x40 = 0100 0000
           ↑
         P0.6
```

因此只有：

```text
P0.6 = 1
```

蜂鸣器响。

而：

```text
P0.4 = 0
```

所以继电器不会跟着吸合。

## 防止蜂鸣器误响的方法

和 `02_ws` 一样：

```text
LED_Write(...)
↓
74HC573 锁存 LED
↓
P0 立即清零
```

这样 LED 的亮灭不会让 `P0.6` 长时间保持为 1。

## 看到 `03_ws` 时要想到

**“闪一次 + 响一次”作为一个整体，再循环 3 次。**

# 04_ws

## 题目

**LED 灯间隔约 500 ms 从右向左依次点亮，间隔约 3 s，重复上述过程，共循环三次。**

## 程序使用的核心变量

```c
unsigned char led_data;
```

每一轮开始：

```c
led_data = 0xFF;
```

即：

```text
11111111
```

全部 LED 熄灭。

随后循环执行：

```c
led_data = led_data << 1;
```

## 数据变化过程

```text
开始：11111111

第 1 次：11111110
第 2 次：11111100
第 3 次：11111000
第 4 次：11110000
第 5 次：11100000
第 6 次：11000000
第 7 次：10000000
第 8 次：00000000
```

因为本实验板：

```text
0 = LED 亮
1 = LED 灭
```

所以效果是：

```text
右边第 1 个灯亮
↓
右边 2 个灯亮
↓
右边 3 个灯亮
↓
……
↓
8 个灯全部亮
```

也就是说，这里的“依次点亮”是：

**前面已经亮的灯保持亮，新的灯继续加入。**

不是“只有一个灯在跑”。

## 延时结构

程序中：

```c
Delay500ms()
```

表示当前使用软件空循环得到的 **近似 500 ms** 延时。

```c
Delay3s()
```

内部执行：

```text
6 × Delay500ms()
```

因此得到近似：

```text
3 s
```

注意：目前还没有使用定时器，所以这些时间只是软件延时的近似值，不是精确定时。

## 三轮结构

```c
for(round = 0; round < 3; round++)
```

整个从右向左依次点亮的过程运行 3 次。

当前代码中：

```c
if(round < 2)
{
    Delay3s();
}
```

所以：

- 第 1 轮结束后等待约 3 s
- 第 2 轮结束后等待约 3 s
- 第 3 轮结束后直接结束

当前 `04_ws` 的实际代码 **没有在第三轮结束后主动把 LED 全灭**，所以最后保持第三轮完成时的状态，即全部点亮。

## 防止蜂鸣器误响

`04_ws` 同样使用：

```text
LED_Write(...)
↓
锁存 LED
↓
P0 = 0x00
```

所以正常 LED 显示阶段不会让 `P0.6` 因 LED 数据而持续为高电平。

## 看到 `04_ws` 时要想到

**移位 `<<` + 从右向左累计点亮 + 500 ms + 3 s + 三轮。**
