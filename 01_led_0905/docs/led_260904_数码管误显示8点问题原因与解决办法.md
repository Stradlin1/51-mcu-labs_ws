# 第一节课补充笔记：LED 程序导致数码管误显示 `8.` 的原因与解决办法

> 适用工程：`led_260904/04_ws`  
> 现象：烧录 LED 从右向左依次点亮程序后，开发板上方数码管意外显示 `8.`。

---

# 一、出现了什么问题

原来的 `LED_Write()` 中有下面这一段：

```c
HC138_C = 1;
HC138_B = 0;
HC138_A = 0;

P0 = dat;

HC138_C = 1;
HC138_B = 0;
HC138_A = 1;

P0 = 0x00;
```

其中：

```text
P2.7 P2.6 P2.5 = 100
```

表示 74HC138 选择 `Y4`。

根据本节课 PPT，`Y4` 用来控制 LED 对应的 74HC573 锁存器，所以这一部分没有问题。

真正的问题出现在后面：

```text
P2.7 P2.6 P2.5 = 101
```

`101` 并不是“关闭 74HC138”或“什么都不选择”，而是：

```text
101 = 5
→ 选择 Y5
```

也就是说，程序从 `Y4` 切换出去以后，并没有进入空闲状态，而是又主动选择了另一条输出 `Y5`。

---

# 二、为什么会出现 `8.`

原程序切到 `Y5` 后马上执行：

```c
P0 = 0x00;
```

于是实际执行过程变成：

```text
选择 Y4
↓
P0 = LED 数据
↓
LED 锁存器得到数据
↓
切换到 Y5
↓
P0 = 00000000
↓
Y5 对应的另一组硬件也接收了这组数据
```

实际烧录后，数码管显示了：

```text
8.
```

对于常见数码管来说，显示 `8.` 意味着：

```text
a b c d e f g dp
全部点亮
```

因此，结合实际现象可以推断：

**Y5 很可能连接到了数码管相关的锁存/控制电路，`P0 = 0x00` 又使对应段全部进入有效状态，所以最终显示成了 `8.`。**

注意：

> 本节课 PPT 只明确说明了 `Y4` 与 LED 控制链的关系，并没有明确说明 `Y5` 具体连接哪个模块。
>
> 所以“Y5 对应数码管相关电路”是根据开发板实际出现 `8.` 的现象做出的推断，而不是 PPT 明确给出的结论。

---

# 三、之前理解错在哪里

之前把下面这三句：

```c
HC138_C = 1;
HC138_B = 0;
HC138_A = 1;
```

简单理解成：

```text
离开 Y4
```

这个说法不够准确。

更准确的理解应该是：

```text
100 → 选择 Y4
101 → 选择 Y5
```

所以：

**“离开 Y4”不代表“什么都不选”。**

74HC138 是 3-8 译码器，只要处于使能状态，三个地址输入就会选择某一路输出。

基本关系可以记成：

```text
000 → Y0
001 → Y1
010 → Y2
011 → Y3
100 → Y4
101 → Y5
110 → Y6
111 → Y7
```

因此改动地址位时，必须考虑：

> 新选中的那一路后面接了什么硬件？

否则就可能出现：

```text
本来只想控制 LED
↓
却误选了另一组硬件
↓
数码管、蜂鸣器、继电器等发生意外动作
```

---

# 四、这次的解决办法

当前 `04_ws` 中，将 `LED_Write()` 改成：

```c
void LED_Write(unsigned char dat)
{
    HC138_C = 1;
    HC138_B = 0;
    HC138_A = 0;

    P0 = dat;

    HC138_C = 0;
    HC138_B = 0;
    HC138_A = 0;

    P0 = 0x00;
}
```

对应流程：

```text
100
↓
选择 Y4
↓
P0 = dat
↓
LED 的 74HC573 接收数据
↓
000
↓
不再选择 Y4，切换到 Y0
↓
P0 = 0x00
↓
避免 P0.6 / P0.4 长时间为 1
↓
蜂鸣器、继电器不误动作
```

在当前开发板实验中，这样处理后避免了原先切到 `Y5` 时出现的数码管 `8.` 问题。

注意：

> PPT 没有给出 Y0 的完整连接关系，所以不能把“Y0 永远是空闲口”当成通用规律。
>
> 当前做法的意义是：根据这块板子的实际实验现象，避免使用已经确认会引发数码管异常的 `Y5`。

---

# 五、为什么还要执行 `P0 = 0x00`

这里的 `P0 = 0x00` 不是为了控制 LED，而是为了避免蜂鸣器和继电器误动作。

本实验板中：

```text
P0.6 = 1 → 蜂鸣器响
P0.4 = 1 → 继电器吸合
```

而 LED 全灭时经常需要写：

```c
P0 = 0xFF;
```

也就是：

```text
11111111
```

其中同时包含：

```text
P0.6 = 1
P0.4 = 1
```

所以不能让 `0xFF` 长时间直接留在 P0 上。

正确思路是：

```text
先选 Y4
↓
把 LED 数据写入 74HC573
↓
让 LED 状态被锁存
↓
再离开 Y4
↓
马上 P0 = 0x00
```

这样：

```text
LED：保持刚才锁存的状态
蜂鸣器：关闭
继电器：关闭
```

# 六、这次故障真正说明了什么

这次问题不是 LED 移位代码本身的问题：

```c
led_data = led_data << 1;
```

也不是延时函数导致的。

真正的问题是：

**同一组 P0 数据线会被多个硬件模块共享，而 P2.5、P2.6、P2.7 通过 74HC138 决定当前哪一组硬件接收 P0 的数据。**

所以以后写这块板子的程序时，要同时考虑两件事：

```text
1. P0 上写了什么数据？
2. 74HC138 当前选中了哪一路？
```

只看其中一个是不够的。

---

# 七、以后遇到类似问题怎么排查

如果以后出现：

```text
控制 LED 时其他模块突然动作
```

按下面顺序检查：

1. 看当前 `P2.7 / P2.6 / P2.5` 是多少；
2. 把三位二进制转换成 `Y0 ~ Y7`；
3. 确认当前到底选中了哪个硬件模块；
4. 再看此时 `P0` 写入的具体数据；
5. 检查这个数据是否会让被选中的模块产生特殊显示或动作；
6. 如果 LED 已经锁存完成，不要随意切到一个未知用途的译码输出后再写 P0。

---

# 八、最短记忆版

```text
100 = Y4 = LED

101 不是“关闭 Y4”
101 = Y5

原程序：
Y4 写 LED
→ 切到 Y5
→ P0 = 0x00
→ 意外控制了 Y5 后面的硬件
→ 数码管显示 8.

当前解决：
Y4 写 LED
→ 切换到当前实验中不会触发数码管异常的 000 状态
→ P0 = 0x00
→ LED 保持锁存
→ 蜂鸣器、继电器不误动作
```

# 九、一句话总结

**74HC138 改地址不是“退出设备”，而是在“切换设备”；所以写 P0 之前，必须先知道当前到底选中了哪一路。**
