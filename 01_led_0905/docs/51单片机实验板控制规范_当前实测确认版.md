# 1. 统一符号

本板中：

```text
HC138_A = P2.5
HC138_B = P2.6
HC138_C = P2.7
```

统一按：

```text
C B A = P2.7 P2.6 P2.5
```

理解。

74HC138 的基本译码关系：

```text
000 -> Y0
001 -> Y1
010 -> Y2
011 -> Y3
100 -> Y4
101 -> Y5
110 -> Y6
111 -> Y7
```

重要：

```text
101 不是“退出 Y4”
101 是明确选择 Y5
```

同理：

```text
000 也不是“什么都不选”
000 是明确选择 Y0
```

所以以后不能随便把某个 `Yx` 当成“安全空闲状态”。

# 3. LED 控制规范

## 3.1 选择 LED

PPT 已明确，且本板实测确认：

```text
CBA = 100
```

即：

```text
P2.7 = 1
P2.6 = 0
P2.5 = 0
```

对应：

```text
100 -> Y4
```

Y4 控制 LED 对应的 74HC573。

推荐写法：

```c
P2 = (P2 & 0x1F) | 0x80;
```

因为：

```text
0x80 = 1000 0000
       ^^^
       P2.7~P2.5 = 100
```

---

## 3.2 LED 的电平逻辑

本板 LED 为低电平点亮：

```text
0 -> LED 亮
1 -> LED 灭
```

所以在：

```text
CBA = 100
```

时：

```text
P0 = 0x00 -> 8 个 LED 全亮
P0 = 0xFF -> 8 个 LED 全灭
```

这已经实测确认。

---

## 3.3 LED 锁存

已经实测确认：

先：

```text
CBA = 100
P0 = 0xFF
```

让 LED 全灭。

然后切到：

```text
CBA = 101
```

之后再改变 P0：

```text
P0 = 0x40
P0 = 0x00
P0 = 0x10
...
```

LED 仍然保持之前的全灭状态。

这说明：

**LED 的 74HC573 已经把之前的数据锁存住。**

因此可以使用下面的思路：

```text
100 -> 写 LED 数据
↓
切到 101
↓
LED 保持刚才的状态
↓
P0 可以继续用于蜂鸣器 / 继电器
```

# 4. 蜂鸣器控制规范

## 4.1 PPT 明确关系

蜂鸣器由：

```text
P0.6
```

控制。

经过 ULN2003 以后，单片机端控制规律为：

```text
P0.6 = 1 -> 蜂鸣器响
P0.6 = 0 -> 蜂鸣器停
```

---

## 4.2 本板实测确认的附加条件

本板实际测试发现：

要正常使用 P0.6 控制蜂鸣器，需要先让：

```text
CBA = 101
```

即：

```text
P2.7 = 1
P2.6 = 0
P2.5 = 1
```

推荐写法：

```c
P2 = (P2 & 0x1F) | 0xA0;
```

因为：

```text
0xA0 = 1010 0000
       ^^^
       P2.7~P2.5 = 101
```

---

## 4.3 蜂鸣器实测状态

在：

```text
CBA = 101
```

条件下：

```text
P0 = 0x40
```

即：

```text
0100 0000
 ^
 P0.6 = 1
```

实测结果：

```text
蜂鸣器响
```

而：

```text
P0 = 0x00
```

即：

```text
P0.6 = 0
```

实测结果：

```text
蜂鸣器停
```

所以当前确认：

```text
101 + 0x40 -> 蜂鸣器响
101 + 0x00 -> 蜂鸣器停
```

# 6. 蜂鸣器和继电器的共同物理开关

本板实测确认：

蜂鸣器和继电器不是两个独立物理开关。

而是：

**蜂鸣器 + 继电器共用一个物理开关。**

这个物理开关控制：

```text
蜂鸣器和继电器是否一起接入工作电路
```

因此：

```text
物理开关 OFF
-> 蜂鸣器和继电器都不参与工作

物理开关 ON
-> 蜂鸣器和继电器都接入电路
-> 再由 P0.6 / P0.4 分别软件控制
```

测试蜂鸣器或继电器程序时：

```text
共同物理开关必须 ON
```

# 7. 蜂鸣器 + 继电器组合控制表

前提：

```text
CBA = 101
```

并且蜂鸣器/继电器共同物理开关：

```text
ON
```

| `0x00` | 0 | 0 | 停 | 释放 |
| `0x10` | 0 | 1 | 停 | 吸合 |
| `0x40` | 1 | 0 | 响 | 释放 |
| `0x50` | 1 | 1 | 响 | 吸合 |

二进制对应：

```text
0x00 = 0000 0000
0x10 = 0001 0000
0x40 = 0100 0000
0x50 = 0101 0000
```

这四种组合已经实际测试通过。

# 8. LED 与蜂鸣器 / 继电器共用 P0 的问题

这一点非常重要。

例如：

```c
P0 = 0xFF;
```

不能只理解成：

```text
LED 全灭
```

因为：

```text
0xFF = 1111 1111
```

其中同时包含：

```text
P0.6 = 1
P0.4 = 1
```

所以如果蜂鸣器/继电器物理开关 ON：

```text
P0 = 0xFF
```

还会导致：

```text
蜂鸣器响
继电器吸合
```

这已经通过实验观察到。

因此：

**LED、蜂鸣器、继电器不能只看 P0 数值，还必须同时看当前 CBA 选中了哪个状态。**

# 9. 推荐的 LED + 蜂鸣器 / 继电器控制顺序

如果程序既需要 LED，又需要蜂鸣器 / 继电器，推荐按下面顺序：

```text
1. CBA = 100
2. P0 写入 LED 数据
3. LED 的 74HC573 锁存
4. CBA = 101
5. 用 P0.6 / P0.4 控制蜂鸣器 / 继电器
```

例如：

```c
P2 = (P2 & 0x1F) | 0x80;
P0 = 0xFF;

P2 = (P2 & 0x1F) | 0xA0;
P0 = 0x00;
```

此时已经实测确认：

```text
LED 保持全灭
蜂鸣器停
继电器释放
```

然后可以继续：

```c
P0 = 0x40;
```

蜂鸣器响，LED 仍保持全灭。

或者：

```c
P0 = 0x10;
```

继电器吸合，LED 仍保持全灭。
